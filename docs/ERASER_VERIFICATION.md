# Native eraser modes and strength — issue #144

The existing sole Eraser popup now controls Hard/Soft, actual diameter in document pixels, and Strength. Both mode buttons have 44-point targets. Reset affects only the selected tool. There is no second toolbar.

New eraser strokes capture an optional versioned descriptor and upgrade the editable document to schema 9. Historical descriptor-free erasers keep their existing clear blend and width multiplier; opening or saving them does not replace their geometry. Existing version-1 tool preferences remain readable when the new optional mode field is absent.

The canonical live/thumbnail/export renderer composites one opaque coverage mask with destination-out and applies strength once per gesture. Hard uses a round outline; Soft blurs that outline by 20% of its diameter, adding a feather outside the core diameter. Zero strength bypasses rendering. Retracing can change antialiased boundary coverage but cannot exceed the gesture's captured strength. Separate gestures can accumulate. The mask affects only its own layer, including managed raster content, and does not modify original imported bytes.

The document validates the descriptor/tool combination, finite diameter and strength, nonempty points, supported version, and limits: 8,192 samples per stroke, 256 styled erasers per frame, 1,024 per document and 65,536 styled eraser samples per document. Invalid commits and typed command batches are transactional. Touch interruption cancels erasing without committing a reusable draft; a cancelled physical drag cannot recapture a different selection. Frame copying and layer duplication preserve eraser metadata with fresh element identities; full-document history restores both schema and pixels.

Hidden, zero-opacity, fully locked, alpha-locked and position-locked layers reject new erasing. Selected drawings now receive their own editable erasure masks (schema 29). Each object is composited in its own isolated layer before its stored destination-out masks are applied, protecting overlapping unselected drawings and imported pixels. The original shape/brush renderer remains in use. A measured native Canvas clipping limitation remains: in the regression with identically overlapping rectangles, four distant partially covered corner pixels can change their lower-object blue/alpha contribution by at most 34/255. Unselected upper red coverage and opaque overlap remain exact. This is not pixel-perfect parity; the original failures and minimal platform probes are retained, and issue #144 remains open. The regression permits only those exact fixture coordinates/channels, with no general image tolerance. Captured inverse affine placement keeps the brush circular at capture and moves the hole with later moves, rotations, scaling and reflection. Original drawing samples remain intact. Copy, paste, frame/layer duplication, Undo/Redo and project storage preserve the masks. The live preview and commit use the same projection and freeze project, revision, frame, layer and selected IDs; changing that context or cancelling the touch cannot broaden erasing to the whole layer. The existing popup offers Deselect drawings.

Selected erasing supports independently rendered drawings and text across explicitly selected visible free layers. The active input layer must also remain editable. Every selected target layer is checked independently; a hidden, zero-opacity, locked or backdrop-dependent target rejects the entire operation without partial erasure. It refuses operation targets and selected layers containing backdrop-dependent pixel effects or alpha-preserving paint. Imported-image selection erasing is not implemented. Deselect to use the existing whole-layer eraser. The existing typed drawStroke command remains fail-closed for nonempty selections. A separate strict eraseSelectedElements command requires literal existing frame/layer references, exact current selected IDs and a fresh project revision; it shares the same atomic editor operation. It preserves selection for pure erasure/rename batches, fences live selection/tool/playback changes, and counts generated and existing nested mask data against command budgets. Masked tween/mirror inputs are rejected rather than losing their holes. Per-object masks are capped at 64 and share the existing aggregate eraser budgets. Issue #144 remains open for these remaining cases and final exact-head verification.
