# Editable Studio text

This bounded #148 slice replaces the Text popup's inert controls with editable text boxes on the canonical document. New text starts at canvas center. Move selects and positions the box; Text → Edit selected edits that same stable identity. The sole popup exposes three system font designs, size, left/center/right alignment, bold, italic, color, opacity, box dimensions and rotation. The native keyboard has a dismissal button. Apply creates one reversible document edit; Cancel changes no artwork. Closing the popup retains the open draft. Save persists committed work but explicitly refuses to report an open text draft as saved or leave Studio.

Schema 10 stores content and a validated versioned text descriptor. Original descriptor-free `fillColor` text keeps its original rendering and encoding. New text survives frame/layer duplication, selection clipboard, translation/reflection, full-document history and actual device persistence. New typography preserves the element ID and its existing translation/reflection. Full, alpha and position locks reject text updates. Limits include 2,048 characters/8,192 UTF-8 bytes per box, 65 paragraphs, 256 boxes per frame and 262,144 text bytes per document. Clipboard and command work estimates include text payloads.

Canvas, thumbnails and exports use the same renderer. It resolves real font metrics for each wrapped line, aligns each line, rotates around the box center and clips to the text box and canvas. Unicode text is retained as entered, with native font fallback. Paragraph shaping and line measurement use SwiftUI's text engine; there are no guessed glyph widths, fake previews or external font dependencies. Box overflow is visibly disclosed as clipped, with resizing available. Text color and layer composition remain in the canonical rendering path.

Spatter uses strict `draw` text descriptors and `updateText` commands through the same production editor. Unknown fields, unsupported versions, invalid combinations, stale revision and cancellation fail without a partial commit. Text drafts prevent unrelated command edits. No provider request, external upload or privileged operation is introduced.

## Remaining scope

Native runtime, independent review, physical device and release acceptance remain required. New text uses explicit creation and Apply, not tap-to-place or a live uncommitted glyph preview. Legacy text can be rendered/exported but has no automatic conversion to the new editable descriptor. Free transform handles, rich text spans, custom font imports, overflow indicators and recovery of a force-quit uncommitted text draft are unfinished. Saved editable text remains protected by the existing atomic document persistence. No exact cross-OS font-pixel parity is claimed.
