# Tool popup height recovery

Native run 35495172041 on source `62e84a2` built the app and passed the production stages, but only 17 of 38 simulator journeys passed. The 21 failures include an empty ScrollView with a zero-height visible frame and unreachable brush, text, selection, image and Hand/Fit controls. The original recording shows the Hand popup header and footer with its operations missing. Original logs, all attachments, full XCResult, diagnostics, app archive and complete recording are retained.

The shared popup accepted the default zero height from preference propagation as its measured content height. That collapsed the viewport. The correction combines measurements with `max` and accepts only positive finite content heights, retaining the previous measurement or initial bounded viewport while a new measurement is unavailable. It preserves the single interactive ScrollView, field focus identities, popup placement, keyboard ownership, close button, per-tool content and document operations.

`Tests/StudioPopupLayout/verify_layout.py` compiles the verbatim production helper with an actual offscreen macOS SwiftUI/NSHostingView fixture. It does not activate an app, boot a simulator, substitute a geometry model or modify production source. Its three cases validate short controls, a scrolling library and compact landscape against actual rendered view bounds. The same harness fails on unchanged `62e84a2` with a zero-height viewport and passes the corrected helper. The workflow runs it before the slower full simulator suite.

SDK compilation, macOS layout and UI-definition compilation do not replace the pending iOS runtime suite. No test timeout, retry policy or assertion was weakened.
