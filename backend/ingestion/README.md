# Private rendered-file intake

Source implementation for #189. Not deployed, not connected to the native client, and not acceptance-tested. No server/listener or cleanup scheduler starts on import.

`UploadStore` owns a private worker directory. SQLite stores actor-bound idempotency keys, metadata, byte counts, expected SHA-256, expiry and registration state. Binary files use server-generated UUID paths. Every chunk is at most 4 MiB and checks its own SHA-256. File bytes are fsynced before offset publication; a crash tail is truncated to the committed offset. Exact duplicate chunks return the committed offset; conflicting offsets or bytes are rejected. Admission reserves the entire declared size against account/global quotas, including completed files until removal. Individual renders are limited to 2 GiB; default retention is 24 hours. Uploaded bytes never replace device originals.

`UploadApplication` is a WSGI adapter for an existing authenticated HTTPS service:

- `POST /v1/render-uploads`: metadata JSON and UUID `Idempotency-Key`.
- `GET /v1/render-uploads/{id}`: authoritative saved offset and state.
- `PATCH /v1/render-uploads/{id}`: binary body, `Upload-Offset`, hex SHA-256 `Upload-Checksum`, explicit Content-Length.
- `POST /v1/render-uploads/{id}/complete`: verifies full digest, validates media and registers a private review.
- `DELETE /v1/render-uploads/{id}`: cancels a receiving upload and removes its owned staged bytes. Registered or uncertain registrations require review withdrawal/reconciliation first.

All routes require a current Bearer session. The injected authorizer must verify signature, issuer/audience, account restrictions, non-anonymous membership and current session revocation against the authorized backend. Identity is never accepted from request JSON. The HTTP gateway must enforce TLS, request-body/read deadlines, concurrency/rate limits, trusted-host routing and no credential logging. Do not expose this via a preview route or bind a development listener publicly.

Begin metadata is exactly `size`, `sha256`, `title`, `source_revision`, `destinations`, `rights_summary`, `consent_version`, `made_for_kids`. The audience classification is an explicit boolean, not a default inferred from a title. Consent must have been collected explicitly; declarations do not establish asset rights. Destinations are an explicit subset of feed/youtube/social. No client field can declare a render approved or bypass Spatter review.

Completion requires two real host adapters: bounded media probing/decoding and idempotent review/artifact registration keyed by upload ID. The registrar must verify current consent/rights and the configured consent version, store a private preview, preserve exact digest and expiry, conservatively require owner review for unverified AI provenance, and return a real review UUID. It must never publish. A durable `registering` state fences cancellation before registration; retries use the same ID when a response is lost. Completion must use immutable private bytes, not a client-local path.

The operator-only bounded `expire` method removes expired receiving bytes. For submitted/uncertain registrations its callback receives upload ID and optional review ID, and must fence new publication claims, expire the registered artifact and ensure all current readers/leases are finished before authorizing deletion. Callbacks and the cleanup schedule still need deployment wiring. Lock files remain to prevent inode replacement races; metadata/lock tombstone compaction requires a separate retention policy.

Final integration must exercise chunk retry/conflict, hash mismatch, interruption at file/DB and registration boundaries, revoked sessions, account/global quotas, media rejection, consent withdrawal, lease-fenced cleanup, native background/resume and actual admin preview/approval. No tests or migration/deployment claims are made for this source-only batch.

## Media adapter

`MediaValidator` supplies real bounded inspection and full video/audio decode via configured operator-installed FFmpeg executables. It accepts one H.264/HEVC video stream and optional stereo AAC, at most 4K/60 FPS and ten minutes by default; foreign streams and malformed media are rejected. No network media protocol is allowed. Process deadlines and output caps are enforced; only the child process group created by the validator is killed on timeout. Use host cgroup/container CPU, memory and file limits as well: an application timeout is not a complete decoder sandbox. No executable was downloaded and no video validation run has been performed yet. Rights and moderation remain separate from successful decoding.

`AccountAuthorizer` calls the configured HTTPS backend's `sdi_upload_identity` RPC using the incoming bearer session and configured publishable key. The gateway validates the token and the unapplied `upload-identity.sql` candidate checks the actual account/session plus non-anonymous identity. There is no identity cache or unsigned-JWT shortcut. Redirects are refused and responses/timeouts bounded; backend errors fail closed. Wire this adapter only after schema reconciliation and authorization verification; no authenticated backend requests were made for this batch.

`ReviewRegistrar` connects the completed private MP4 to the existing review/artifact tables using the server credential and unapplied `upload-registration.sql`. The registration transaction locks the upload identity, rejects changed metadata on retry, and returns the same review ID after an uncertain response. It never resets previously withdrawn consent or restores approval. It stores an actual relative server object key plus checksum/size, not an iOS-local path. Rights remain uncleared and unknown AI provenance requires owner approval. Current consent version is host-configured. A host-provided private preview issuer/range server remains required; no permanent public file URL is generated. The admin rights-clearance workflow and preview renewal/retention integration remain pending. No service credential is sent to the native client.

## Protected preview playback

`PreviewLinks` signs a render-bound bearer capability with an operator-held key (at least 32 random bytes), expiring after ten minutes by default (maximum fifteen). Only protected review responses receive these links; possession grants playback until expiry/revocation, so gateway and analytics logs must redact the entire URL token. `PreviewApplication` supports bounded-memory GET/HEAD and single byte ranges for AVPlayer. `ReviewRegistrar.preview_authority` consults the unapplied `upload-preview.sql` service RPC before streaming and at least every five seconds during long responses; expired/withdrawn/rejected/blocked creator artifacts fail closed. A shared file lock prevents retention from deleting bytes while being read. The iterable closes handles even when the client disconnects before consuming any data. No listener is started.

These are implementation components, not a configured live URL. Preview renewal by an authorized reviewer remains needed for queues older than the short capability lifetime. Signing-key provisioning, existing-host HTTPS/rate limits/log redaction, final runtime/range/cancellation verification and native upload remain outstanding. No real preview or service RPC was invoked.

## Preview renewal and artifact retention

Artifact expiry now uses the original upload's retained-until time, independently of the short preview capability. Intake passes that server timestamp to registration; the client cannot extend retention. The unapplied `preview-renewal.sql` issues one-minute, single-use permits through the requesting admin's current MFA session. The host checks retained bytes under a shared lock, signs a new capability and fulfills the permit with its server credential. Fulfillment rechecks session/role/account, exact digest/version, consent and artifact expiry. It updates only preview URL/expiry, leaving render approval/version untouched. Expired files are not resurrected. Per-admin issuance is bounded; consumed permits remain until their one-minute rate window expires.

Wire `ReviewRegistrar.renew_preview` to `UploadApplication`'s optional renewal callback for `POST /v1/review-previews/{reviewID}/renew` with digest/version JSON and the current bearer token. No callback means explicit unavailable. Native renewal UI and host deployment/verification are still pending; no API call or SQL apply was performed.

## Native submission screen

Profile → Publishing → Upload an exported MP4 for review stages an explicitly chosen Files MP4, captures title/source description/rights declaration, explicit audience classification and independent feed/official-channel/social-marketing permissions. A configured current terms URL/version and authenticated account are required before staging. The user starts/resumes the transfer explicitly; background/navigation/account changes pause the task and preserve its journal. The receipt says private review, never published. Removal is confirmed and affects only the app-owned staged copy. The native current-session token is acquired for each network operation and never persisted.

Required public build settings: SDI_UPLOAD_SERVICE_URL, optional SDI_RENDER_PREVIEW_URL, SDI_PUBLISHING_CONSENT_VERSION and SDI_PUBLISHING_TERMS_URL. No values or legal terms were invented. The transfer is foreground resumable, not an installed background URLSession uploader; automated retry/backoff and true background delivery remain pending. No native/source build, file-picker run, upload or deployment was performed for this implementation batch.

## Native bounded retry policy

GET and idempotent upload creation allow at most three attempts for transient connection/timeouts or 429/5xx responses, honoring bounded Retry-After delays. Each binary chunk permits at most two automatic recovery cycles. A cycle waits, reads the authoritative server offset and only then resends missing bytes; a lost successful response does not duplicate data. Retry count/delay are recorded in the upload journal. Explicit user Resume starts a new bounded attempt window; there is no autonomous infinite reconnect loop. Authorization, invalid metadata, expired uploads and checksum failures stop for user action. Completion remains an explicit same-upload reconciliation on Resume rather than an unbounded expensive media-validation retry. Actual fault-injection and device verification remain deferred.

## Bounded operator retention

The unapplied `upload-retention.sql` candidate adds service-only retirement authorization. It locks registration/review/job records, requires every artifact version using the upload to have expired, refuses active/grace-period leases and unresolved worker/provider states, and cancels queued/failed publication attempts. Already published results are retained. Incomplete known provider uploads enter removal_pending; provider cleanup remains a separate workflow. Unknown registration outcomes preserve bytes for reconciliation. Local preview readers are separately protected by the store's exclusive file lock. No device original is touched.

After migrations and host verification, the operator maintenance entry point is `python -m backend.ingestion.retention --execute --limit 25`, using the same private environment as intake. This is an explicit deletion command, not a preview; it has not been executed here. It examines at most 100 candidates and reports only aggregate removed count. A false retirement response, RPC outage or malformed response preserves submitted bytes. Repeat calls reconcile a prior database authorization with a later interrupted file deletion. Configure the approved host's scheduler with one execution at a time, bounded duration/backoff and private diagnostics; no scheduler or system service was installed in this batch. Unresolved registrations/leases require operator reconciliation rather than silent age-based deletion.
